2.1 Standard Data Types

Definitions, purpose and use 2.1.1

TypeDefinitionPurpose and suitable useExamples

FloatA number that can contain a fractional/decimal part.Measurements, averages and values requiring decimal places.3.5, -0.25

Common misconceptionA value containing digits is not automatically numeric. A telephone number or product code may be stored as a string because arithmetic is not performed on it.

2.2 Variables and Constants

Variables and constants 2.2.1–2.2.2

  • Variable: a named storage location whose value can change while a program runs.
  • Constant: a named value intended not to change while the relevant program runs. Python uses a naming convention such as MAX_ATTEMPTS to communicate this intention.
MAX_ATTEMPTS = 3
attempts = 0
attempts = attempts + 1

Data type conversion 2.2.3, 2.2.9

Conversion functions change a value into a required data type. Keyboard input is returned as a string, so conversion is often needed before calculations.

age = int(input("Enter age: "))
price = float(input("Enter price: "))
message = str(25)
is_active = bool(1)

Scope 2.2.4–2.2.6

ScopeMeaningUse and consideration
GlobalDefined at module level and accessible according to Python scoping rules; a local name can shadow it.May be needed by several parts, but widespread use can make changes and testing harder to control.
LocalCreated within a function/procedure and available there.Limits unintended changes and makes the part easier to understand and test.
discount_rate = 0.10

def calculate_discount(price):
    discount = price * discount_rate
    return discount

Declare and use variables/constants 2.2.7–2.2.8

Select a suitable data type, meaningful name and initial value. Use a variable where the value changes and a constant where it should remain stable.

Conversion limits: not every string can be converted to a number. Failed conversions may need validation or exception handling. Python does not enforce uppercase constants. bool("False") is True because the string is non-empty; it does not parse the word as a Boolean value.

2.3 Data Structures

Purpose and use 2.3.1

StructureDefinitionSuitable use
ListAn ordered collection of values accessed by position/index.A sequence whose items need to be stored, processed or changed.
ArrayAn indexed collection generally intended for values of a common type.Related values requiring consistent indexed access. Use the representation supplied in the question or approved teaching context; do not assume an additional library is required.
DictionaryA collection of key–value pairs.Looking up a value using a meaningful key rather than only a numerical position.

Interpret, develop and debug 2.3.2–2.3.4

scores = [12, 18, 9]
student = {"id": 101, "name": "Amina"}

scores.append(21)
student["name"] = "Amira"

print(scores[0])
print(student["name"])
Common errorsUsing an index outside the available positions, misspelling a dictionary key, or selecting a structure that does not suit the required access.

List operations from the supplied Appendix

Use index(), append(), insert(), remove(), count(), pop(), sort(), in, not in and len().

Worked teaching example — not an assessed question.

names = ["Aisha", "Ben"]
names.append("Cara")
names.insert(1, "Dylan")
names.remove("Ben")
last_name = names.pop()
names.sort()
position = names.index("Aisha")
occurrences = names.count("Aisha")
number_of_names = len(names)
found = "Aisha" in names
absent = "Ben" not in names

Lists are mutable ordered collections. Dictionaries are mutable key–value collections. Choose by the required access and relationships, rather than treating them as interchangeable.

2.5 Input and Output

Keyboard, screen and text file 2.5.1

name = input("Enter name: ")
print("Hello", name)

Text files 2.5.2

Students need to understand opening a file for reading or writing, writing lines and closing the file.

output_file = open("results.txt", "w")
output_file.write("Amina,18\n")
output_file.close()

input_file = open("results.txt", "r")
line = input_file.readline()
input_file.close()
print(line.strip())

Interpret, create and debug 2.5.3–2.5.5

Check file mode, filename, conversion of input, use of newline characters and whether a file is closed after use.

Reading and splitting text

read() reads remaining text; readline() reads one line; readlines() returns remaining lines as a list. strip() removes leading/trailing whitespace by default; split() divides text using a separator. Opening with "w" replaces existing file content.

Worked teaching example — not an assessed question.

file = open("students.txt", "r")
for line in file.readlines():
    parts = line.strip().split(",")
    print(parts[0])
file.close()

This example assumes the file exists and contains the stated comma-separated records. File-writing examples use the two-character escape \n inside a string to write a newline.

2.6 Actions

Sequence 2.6.1

Instructions are executed in a logical order. Incorrect order may produce inaccurate output or an error.

Selection 2.6.2

Selection chooses which instructions run using if, elif, else or match/case.

if score >= 70:
    status = "High band"
elif score >= 50:
    status = "Middle band"
else:
    status = "Lower band"

Loops and iteration 2.6.3–2.6.4

LoopUse
Count-controlled forUsed when iterating over a known range or collection.
Condition-controlled whileUsed while a condition remains true, often when the number of repetitions is not known beforehand.
for number in range(5):
    print(number)

password = ""
while password != "secure123":
    password = input("Password: ")

Benefits and drawbacks of loops 2.6.5

BenefitsDrawbacks
Reduce repeated code; process collections; automate repetition.Incorrect conditions can create infinite loops; incorrect bounds can miss or repeat values; excessive repetition can reduce efficiency.

Interpret, develop and debug actions 2.6.6–2.6.8

Trace the order, decisions and repetitions. Check conditions, updates, indentation and termination.

The selection thresholds above are illustrative software rules, not Pearson qualification grade boundaries.

Selection with match/case

Worked teaching example — not an assessed question.

menu_choice = 2
match menu_choice:
    case 1:
        print("Add")
    case 2:
        print("View")
    case _:
        print("Invalid")

2.7 Functions and Procedures

Characteristics 2.7.1–2.7.2

ConstructParametersReturn
FunctionMay or may not take parameters.Must return a result.
ProcedureMay or may not take parameters.Must not return a result.
def calculate_total(price, quantity):
    return price * quantity

def display_message(message):
    print(message)

Sources of code 2.7.3

  • User-written.
  • Pre-written and built into the language.
  • Pre-written in libraries supplied with the language.
  • Pre-written in third-party libraries.

Pre-written code: benefits and drawbacks 2.7.4

BenefitsDrawbacks
Can reduce development time; avoids recreating existing functionality; may have been widely used/tested.May not meet exact requirements; creates dependency on external code; may contain defects or security issues; developer must understand correct use.

Interpret, develop and debug 2.7.5–2.7.7

Check parameters, arguments, returned values, function calls and whether a function/procedure matches the required purpose.

The function/procedure distinction above uses the qualification terminology. Python implements both with def; a call with no explicit return value returns None. A procedure performs its action without explicitly returning a useful result.

Built-in operations in supplied scope

range() generates an integer sequence; round() rounds; max() and min() select extremes; chr() converts a character code to a character; ord() converts a single character to its code; len() gives length. count() is used as a collection/string method, not a standalone Python built-in.

Math library

Worked teaching example — not an assessed question.

import math
radius = 3
rounded_down = math.floor(4.8)
rounded_up = math.ceil(4.2)
truncated = math.trunc(-4.8)
root = math.sqrt(81)
power = math.pow(2, 5)
circumference = 2 * math.pi * radius

floor() rounds down; ceil() rounds up; trunc() removes the fractional part towards zero. sqrt() finds a square root; pow() calculates a power; pi supplies π.

Random library

Worked teaching example — not an assessed question.

import random
items = ["red", "green", "blue", "gold"]
value = random.random()
whole = random.randint(1, 10)
decimal = random.uniform(1.0, 5.0)
selection = random.sample(items, 3)

random() produces a float from 0 inclusive to 1 exclusive; randint() includes both integer endpoints; uniform() produces a float in the supplied interval, with endpoint behaviour affected by floating-point rounding; sample() selects without replacement. Random-output questions must provide generated values or ask about possible outcomes, not demand one unpredictable output.

Dates and times

Worked teaching example — not an assessed question.

from datetime import datetime
now = datetime.now()
display_date = now.strftime("%d/%m/%Y")
parsed_date = datetime.strptime("16/10/2026", "%d/%m/%Y")

now() supplies the current date/time; strftime() formats it as text; strptime() parses text using a specified format. Supply the import style, relevant format codes and any fixed date/time needed by an assessed task.

2.8 Validation

Definition, purpose and checks 2.8.1

Validation checks whether input follows defined rules and is acceptable for processing. It does not prove that the value is factually correct.

CheckPurposeExample
PresenceEnsures data has been entered.Name must not be blank.
LengthChecks the number of characters.Password must contain at least 8 characters.
RangeChecks a value is between allowed limits.Score must be 0–100 inclusive.
TypeChecks data is of the required type.Quantity must be an integer.
FormatChecks data follows a required pattern.Reference begins with two letters.
Check digitUses a calculated digit to detect certain input errors.Product or identification code.

Interpret, develop and debug 2.8.2–2.8.4

score = int(input("Enter score: "))
while score < 0 or score > 100:
    print("Score must be from 0 to 100")
    score = int(input("Enter score: "))
Validation is not verificationValidation checks compliance with rules. A plausible but incorrect value may pass validation.

The score example assumes input can be converted to an integer; it checks range but does not handle non-numeric input. Choose checks and recovery behaviour to meet the complete requirement.

String handling for validation and processing

  • isupper(), islower(): check case; upper(), lower(): return case-converted strings.
  • isalpha(), isalnum(), isdigit(): test alphabetic, alphanumeric and digit content. A digit check alone does not establish every numeric input requirement.
  • find() returns the first substring position or -1 if absent; index() raises an error when the requested value is absent.
  • replace() returns text with replacements; strip() removes leading/trailing whitespace or specified characters; split() returns parts.
  • len() gives length; format() inserts formatted values; + concatenates strings, with conversion where needed.

Worked teaching example — not an assessed question.

reference = "  ab12  "
cleaned = reference.strip().upper()
valid = len(cleaned) == 4 and cleaned.isalnum()
message = "Reference: {}".format(cleaned)
print(message)

2.9 Design Considerations and Programming Practices

Logical order and order of operations 2.9.1–2.9.2

Actions and calculations must be ordered so outputs are accurate and errors are avoided. Parentheses can make intended calculation order clear.

Efficiency choices 2.9.3–2.9.4

Select data structures and order actions with execution time and memory use in mind. Avoid unnecessary processing or storage while still meeting requirements.

Naming and readability 2.9.5–2.9.6

  • Use meaningful names.
  • Recognise and use camelCase and snake_case.
  • Use whitespace consistently.
  • Avoid line lengths that make code difficult to read or display.
# Unclear
x = p * q

# Clearer
total_price = unit_price * quantity

Judge algorithm suitability 2.9.7

Required judgement factors
  • meeting requirements;
  • storage efficiency;
  • execution time;
  • choice of data structures and data types;
  • use of variables and constants;
  • presentation;
  • maintainability.

A justified judgement applies these factors to the scenario, considers strengths or limitations and concludes whether the algorithm is suitable.

2.10 Robust Code

Characteristics 2.10.1

  • Handles unexpected inputs.
  • Handles unexpected terminations.
  • Produces specific and meaningful error messages.
quantity = input("Enter quantity: ")

if quantity.isdigit():
    quantity = int(quantity)
    print("Quantity accepted")
else:
    print("Quantity must be a whole number")

Debugging 2.10.2–2.10.5

Debugging is used to locate and correct errors. It supports robust solutions by removing faults that cause incorrect output, failure or unsuitable handling of data.

  1. Identify the expected behaviour.
  2. Locate the error.
  3. Correct the error.
  4. Run the relevant code again to check the correction.
Common weaknessChanging several unrelated parts at once can make it harder to determine which correction solved the problem or introduced another fault.

The digit-check example only illustrates non-negative integer input; it does not establish every possible range, recovery or failure requirement.

Handling conversion errors

Worked teaching example — not an assessed question.

try:
    quantity = int(input("Quantity: "))
    if quantity < 1:
        print("Quantity must be at least 1")
    else:
        print("Quantity accepted")
except ValueError:
    print("Enter a whole number")

This handles a conversion error for one attempt. If the requirement is to retry until valid, add a suitable loop. Robustness requires controlled behaviour, relevant validation, meaningful messages and handling the stated failure conditions; try/except alone is not proof of robustness.

2.11 Common Algorithms

Searching 2.11.1, 2.11.3, 2.11.6

AlgorithmHow it worksBenefitsDrawbacks/suitability
Linear searchChecks each item in order until the target is found or all items have been checked.Simple; works with unsorted data.May require many comparisons; suitable for small or unsorted collections.
Binary searchCompares the target with the middle item in sorted data and repeatedly discards half of the remaining search area.Can use far fewer comparisons on large sorted data.Requires sorted data; sorting first may add work if searches are infrequent.

Sorting 2.11.2–2.11.3, 2.11.7

AlgorithmHow it worksBenefitsDrawbacks/suitability
Bubble sortRepeatedly compares adjacent items and swaps those in the wrong order until no further swaps are needed.Simple to understand and implement.Often many comparisons/swaps; generally unsuitable for large collections.
Insertion sortBuilds a sorted section by taking each new item and inserting it into its correct position.Can work well for small or nearly sorted collections.Can require many movements/comparisons for large, disordered data.
Merge sortDivides data into smaller groups, sorts them and merges them into ordered results.Predictable performance for larger collections.Requires additional memory during merging and is more complex.

Comparison metrics and cases 2.11.4–2.11.5

  • Memory space: additional storage required.
  • Execution time: time taken to complete.
  • Number of comparisons: how often values are compared.
  • Best case: most favourable arrangement/input.
  • Worst case: least favourable arrangement/input.
  • Average case: expected behaviour across typical arrangements/inputs.
Suitability judgementUse the dataset's size/order, frequency of use, memory limits, execution needs and number of comparisons. Big O notation is not required.

Worked search example

Worked teaching example — not an assessed question.

values = [14, 7, 22, 9]
target = 22
position = -1
for index in range(len(values)):
    if values[index] == target:
        position = index
        break
print(position)

The linear search reports index 2 after comparing three values. For absent targets it examines all items. For binary search, the sorted/indexable-data requirement and any preparation cost matter. Compare actual implementations: an early-exit bubble sort and a fixed-pass variant can have different best-case behaviour.

2.12 Testing

Testing components 2.12.1.1

Test software, hardware, data, interfaces and the resulting service individually before combining them. This helps locate component-level faults before integration makes diagnosis harder.

Macros, scripts and functional testing tools automate repeated tests. Automation is useful for consistent repetition, but tests still need suitable design and maintenance.

Revision-agent guidance

This section records the supplied agent configuration as reference guidance. The shared approved Pearson specification takes precedence over this website. If a conflict is identified, follow that specification and briefly flag the difference.

Scope and session structure

  • Use British English, a friendly, encouraging, exam-focused tone and Level 3 terminology. Retain the exact Pearson terminology needed for assessment.
  • Assess Content Area 2 only, references 2.1.1–2.12.4.3. Code is Python 3.10 or later and uses the supplied specification/Appendix scope; do not make advanced or unlisted programming knowledge a requirement for credit.
  • Ask the learner to choose a topic or offer the ordered 12-topic revision route, sections 2.1–2.12. Ask whether they want guided revision or exam practice.
  • For guided revision, complete the explanation of meaning, terminology, links, a software-development example, misconceptions and an exam tip. Check readiness before assessed questions.

Answer-safe practice

  • Complete explanations before retrieval or exam practice. Label worked examples as teaching material and keep them separate from assessed questions.
  • Use fresh scenarios, entities and values for later questions. Do not copy or lightly reword an example whose solution the learner has just seen.
  • Do not place a question beside its answer, model response, completed sentence or answer-bearing hint. Do not ask recap questions when nearby headings or examples reveal the answer.
  • Ask one closed-book question at a time and wait for the learner’s response before marking. Do not display the remaining questions or marking guidance.
  • Do not provide answer choices unless the learner explicitly requests multiple choice. Offer a scaffolded retry before revealing a complete answer; the scaffold must not disclose it.

Four-question exam practice

  • Prepare four questions for the selected topic and present them individually. Progress broadly from knowledge and understanding to application, analysis and evaluation, as the topic permits.
  • Give suitable prominence to AO2 with concise software-development scenarios. Generic definitions cannot earn full application credit where use of the context is required.
  • Before each question, check scope, specification reference, an appropriate Pearson command word, clear marks, unambiguous requirements and no answer leakage.
  • For tracing, supply complete starting values and inputs. For correction, state intended behaviour. For translation, preserve the logic across notations. For design, give sufficient requirements.
  • Keep unrelated code complexity low. Verify syntax, stated requirements, input assumptions and outputs. For testing, provide exact rules and distinguish expected results from observed actual results. Accept alternative correct Python unless a named construct is required.

Marking and feedback

  • Prepare an internal indicative marking guide before asking each question; do not reveal it before the learner attempts the question. Match the command word and marks consistently.
  • Award terminology-dependent marks only for the required Pearson term or an unmistakably exact equivalent. Accept equivalent valid representations where permitted by the question.
  • After each response, give the mark awarded, what was successful, what is missing and one specific improvement. Offer a scaffolded retry before a complete answer.
  • After four questions, summarise strengths, two priority revision areas and a recommended next step. Do not claim results are stored or saved.
  • Generated practice and indicative marking are teaching material, not official Pearson questions, mark schemes or a prediction of examination results.

Common misconceptions and corrections

  • input() returns a string, not an automatically converted number.
  • = assigns; == compares. / performs true division; // performs floor division; % returns a remainder.
  • Python constants are intended fixed values, communicated through convention; uppercase names do not enforce immutability.
  • Global variables are not automatically preferable. Shared state can complicate understanding, maintenance and testing.
  • Validation checks rules, not factual truth. Different validation checks meet different requirements.
  • In the qualification distinction, a function returns a result and a procedure performs an action without returning a useful result. Python uses def for both.
  • A while loop is condition-controlled. A for loop commonly iterates over a count or collection.
  • Binary search requires appropriately sorted data. The algorithm with fewer comparisons is not automatically best when preparation cost, memory and requirements are considered.
  • Integration testing checks combined components; “incremental testing” is not an interchangeable label.
  • Boundary testing covers relevant limits and adjacent values, not only the maximum. Testing valid data alone is insufficient.
  • System testing checks the integrated system; acceptance testing checks agreed user/customer needs.
  • Robustness is more than using try/except. Testing cannot prove that every possible defect is absent.
